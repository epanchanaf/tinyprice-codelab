Lo que vas a construir

TinyPrice recibe una consulta, muestra un estado de carga, presenta hasta diez resultados y conserva el enlace de cada fuente. El usuario puede abrir un resultado, revisar sus detalles y saltar al sitio original.

Trabajarás en tres lugares distintos. En el navegador crearás las cuentas y configurarás los servicios alojados. En Android Studio escribirás la aplicación Kotlin y la ejecutarás en un emulador. En la terminal, situada en la carpeta del proyecto, compilarás la app y desplegarás la función de Supabase. El codelab es la guía: los comandos no se ejecutan dentro de esta página.

⌕

◫

◇

Secreto protegido

Ruta del laboratorio

Los bloques están ordenados según las dependencias de la práctica. Cada uno deja preparado algo que utilizarás más adelante; por eso conviene comprobar el resultado antes de continuar.

  1. TinyFish, pasos 3–4. Crea la cuenta con el enlace de referido, obtiene una API key y comprueba qué tipo de respuesta ofrece Search. Guarda la clave en un gestor de contraseñas.
  2. Android, pasos 5–9. Construye la interfaz y el flujo de búsqueda con datos ficticios. Así puedes probar pantallas y navegación sin depender todavía de un servidor.
  3. Supabase Cloud, pasos 10–13. Crea un proyecto alojado, implementa la función y guarda allí la clave de TinyFish. La función será el intermediario entre la app y Search.
  4. Integración y calidad, pasos 14–16. Cambia la app a datos remotos, prueba el recorrido completo y revisa cómo diagnosticar errores.
Qué significa “raíz del proyecto”

Es la carpeta IATinyFish/, donde están gradlew, app/ y, más adelante, supabase/. Cuando el codelab diga “desde la raíz”, abre una terminal en esa carpeta antes de ejecutar el comando.

Cuatro términos que usarás durante el laboratorio

Una API es una forma acordada de pedir datos a otro servicio. La API key identifica a quien hace la petición; por eso la de TinyFish es privada y se guarda en Supabase, no en la app. Una Edge Function es código que se ejecuta en los servidores de Supabase cuando recibe una solicitud. El APK es el archivo instalable de Android: cualquier persona podría inspeccionarlo, así que no debe contener secretos.

También verás la palabra repositorio: aquí significa la pieza de Kotlin que obtiene ofertas para la interfaz. Primero devolverá datos de demostración y después consultará la función remota. Este cambio te permitirá distinguir un problema de pantalla de un problema de red.

Arquitectura y recorrido de una búsqueda

Antes de escribir código, ubica cada responsabilidad. El diseño evita que Android conozca la clave de TinyFish y permite reemplazar los datos de demostración por resultados reales sin cambiar la UI.

Dónde trabajar

Lee este paso en el codelab y dibuja el recorrido en tus apuntes si te ayuda. Todavía no necesitas abrir Android Studio, registrarte ni ejecutar comandos.

Las tres piezas

Piensa en una búsqueda escrita por una persona. La app recibe el texto, Supabase lo envía al proveedor usando una clave privada y TinyFish devuelve enlaces de páginas web. Supabase convierte esa respuesta a un formato sencillo antes de devolverla al teléfono. Así cada componente tiene una responsabilidad que podrás comprobar por separado.

1AndroidCompose · ViewModel · Repository
POSTquery→
2Supabase CloudValidación · secreto · transformación
GETX-API-Key→
3TinyFish SearchResultados web estructurados
← La respuesta vuelve como { "offers": [...] } ←

Contrato de entrada y salida

Android envía una consulta sencilla. La función valida el texto, consulta TinyFish y adapta cada resultado al modelo que la app ya entiende.

En la solicitud solo viaja query, que es lo que escribió el usuario. La respuesta contiene offers, una lista de elementos que Android puede mostrar. El campo sourceUrl permite comprobar el origen de cada resultado. Observa que ninguno de estos ejemplos contiene la API key: la función la lee desde Supabase, no desde la app.

Solicitud

{
  "query": "Nintendo Switch OLED"
}

Respuesta

{
  "query": "Nintendo Switch OLED",
  "offers": [
    {
      "id": "1-https://tienda.example/...",
      "store": "Tienda",
      "productName": "Nintendo Switch OLED",
      "price": "Ver en fuente",
      "sourceUrl": "https://...",
      "summary": "Fragmento del resultado",
      "tags": ["Resultado web"]
    }
  ],
  "searchedAt": "2026-10-15T15:00:00.000Z"
}
Por qué el precio puede decir “Ver en fuente”

TinyFish Search devuelve descubrimiento web —título, URL, fragmento y metadatos—, no garantiza un campo de precio normalizado. TinyPrice conserva la fuente y evita inventar datos que el proveedor no entregó.

Estrategia por etapas

Primero prepararemos el acceso a TinyFish y guardaremos su clave fuera del proyecto. Después construiremos Android con datos locales; luego crearemos el servicio en la nube y, solo cuando el endpoint responda bien, activaremos el repositorio remoto. Esta secuencia reduce la superficie de diagnóstico.

Al terminar la demo de Android verás productos de ejemplo. Eso es correcto en esa etapa: demuestra que la interfaz y el estado funcionan. Los resultados web aparecerán solo después de desplegar Supabase y activar la configuración remota de la app.

class RemoteDealsRepository(
    private val api: TinyPriceApi = TinyPriceApiFactory.create(),
    private val gson: Gson = Gson(),
) : DealsRepository {
    override val isPreviewData = false

    override suspend fun search(query: String): List<ProductOffer> =
        withContext(Dispatchers.IO) {
            try {
                val response = api.searchProducts(SearchProductsRequest(query))
                if (!response.isSuccessful) {
                    throw RemoteSearchException(response.errorMessage())
                }
                response.body()?.offers.orEmpty().map { it.toProductOffer() }
            } catch (error: RemoteSearchException) {
                throw error
            } catch (_: Exception) {
                throw RemoteSearchException(
                    "No se pudo conectar con la búsqueda en vivo. Revisa tu conexión e inténtalo de nuevo.",
                )
            }
        }

    private fun Response<*>.errorMessage(): String = runCatching {
        errorBody()?.charStream()?.use { reader ->
            gson.fromJson(reader, ApiErrorResponse::class.java)?.error
        }
    }.getOrNull().orEmpty().ifBlank {
        "No fue posible hacer la búsqueda en vivo. Inténtalo de nuevo."
    }
}

import androidx.lifecycle.ViewModel

import com.apps.iatinyfish.data.model.ProductOffer

import com.apps.iatinyfish.data.repository.DealsRepositoryProvider

import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.update
import kotlinx.coroutines.launch
import kotlinx.coroutines.Job

data class DealsUiState(
    val query: String = "",
    val offers: List<ProductOffer> = emptyList(),
    val hasSearched: Boolean = false,
    val isLoading: Boolean = false,
    val errorMessage: String? = null,
    val isPreviewData: Boolean = true,
    val selectedOffer: ProductOffer? = null,
)

sealed interface DealsEvent {
    data class QueryChanged(val value: String) : DealsEvent
    data object SubmitSearch : DealsEvent
    data class UseSuggestion(val value: String) : DealsEvent
    data class OpenOffer(val offer: ProductOffer) : DealsEvent
    data object Back : DealsEvent
}

class DealsViewModel(
    private val repository: DealsRepository = DealsRepositoryProvider.create(),
) : ViewModel() {
    private var searchJob: Job? = null
    private val _state = MutableStateFlow(DealsUiState(isPreviewData = repository.isPreviewData))
    val state: StateFlow<DealsUiState> = _state.asStateFlow()

    fun onEvent(event: DealsEvent) {
        when (event) {
            is DealsEvent.QueryChanged -> _state.update {
                it.copy(query = event.value, selectedOffer = null, errorMessage = null)
            }
            DealsEvent.SubmitSearch -> search(_state.value.query)
            is DealsEvent.UseSuggestion -> {
                _state.update { it.copy(query = event.value, selectedOffer = null, errorMessage = null) }
                search(event.value)
            }
            is DealsEvent.OpenOffer -> _state.update { it.copy(selectedOffer = event.offer) }
            DealsEvent.Back -> _state.update { it.copy(selectedOffer = null) }
        }
    }

    private fun search(query: String) {
        if (query.isBlank()) {
            _state.update {
                it.copy(
                    hasSearched = true,
                    offers = emptyList(),
                    errorMessage = "Escribe un producto para iniciar la búsqueda.",
                )
            }
            return
        }

        searchJob?.cancel()
        searchJob = viewModelScope.launch {
            _state.update {
                it.copy(isLoading = true, hasSearched = true, selectedOffer = null, errorMessage = null)
            }
            try {
                val offers = repository.search(query)
                _state.update { it.copy(offers = offers, isLoading = false) }
            } catch (error: RemoteSearchException) {
                _state.update {
                    it.copy(offers = emptyList(), isLoading = false, errorMessage = error.message)
                }
            }
        }
    }
}

const corsHeaders = {
  "Access-Control-Allow-Origin": "*",
  "Access-Control-Allow-Headers": "authorization, x-client-info, apikey, content-type",
  "Access-Control-Allow-Methods": "POST, OPTIONS",
  "Content-Type": "application/json; charset=utf-8",
};

const requestTimes = new Map<string, number[]>();
const MAX_REQUESTS_PER_MINUTE = 20;

function json(body: unknown, status = 200) {
  return new Response(JSON.stringify(body), { status, headers: corsHeaders });
}

function isRateLimited(request: Request) {
  const now = Date.now();
  const key = request.headers.get("x-forwarded-for")?.split(",")[0]?.trim()
    ?? "anonymous";
  const recent = (requestTimes.get(key) ?? [])
    .filter((timestamp) => timestamp > now - 60_000);

  if (recent.length >= MAX_REQUESTS_PER_MINUTE) {
    requestTimes.set(key, recent);
    return true;
  }
  recent.push(now);
  requestTimes.set(key, recent);
  return false;
}

function offerFromResult(
  result: Record<string, unknown>,
  position: number,
  query: string,
) {
  const rawUrl = typeof result.url === "string" ? result.url : "";
  let sourceUrl = "";
  const siteName = typeof result.site_name === "string" ? result.site_name : "";
  let store = siteName;
  try {
    const parsedUrl = new URL(rawUrl);
    if (parsedUrl.protocol === "http:" || parsedUrl.protocol === "https:") {
      sourceUrl = parsedUrl.toString();
      store ||= parsedUrl.hostname.replace(/^www\./, "");
    }
  } catch {
    store ||= "Fuente web";
  }

  return {
    id: `${position}-${sourceUrl || query}`,
    store,
    productName: typeof result.title === "string" ? result.title : query,
    price: "Ver en fuente",
    originalPrice: null,
    shipping: "Consulta en tienda",
    delivery: "Disponibilidad por confirmar",
    rating: "—",
    sourceUrl,
    summary: typeof result.snippet === "string"
      ? result.snippet
      : "Resultado encontrado en la web.",
    tags: ["Resultado web"],
    isBestValue: false,
  };
}

Deno.serve(async (request) => {
  if (request.method === "OPTIONS") {
    return new Response("ok", { headers: corsHeaders });
  }
  if (request.method !== "POST") {
    return json({ error: "Usa una solicitud POST para buscar." }, 405);
  }
  if (isRateLimited(request)) {
    return json({ error: "Demasiadas búsquedas. Inténtalo en un minuto." }, 429);
  }

  let query = "";
  try {
    const body = await request.json();
    query = typeof body?.query === "string" ? body.query.trim() : "";
  } catch {
    return json({ error: "El cuerpo debe ser JSON válido." }, 400);
  }
  if (query.length < 2 || query.length > 200) {
    return json({ error: "La búsqueda debe tener entre 2 y 200 caracteres." }, 400);
  }

  const apiKey = Deno.env.get("TINYFISH_API_KEY");
  if (!apiKey) {
    return json({
      code: "TINYFISH_NOT_CONFIGURED",
      error: "La búsqueda en vivo aún no está configurada.",
    }, 503);
  }

  const searchUrl = new URL("https://api.search.tinyfish.ai");
  searchUrl.searchParams.set("query", query);
  searchUrl.searchParams.set("purpose", "Encontrar páginas de compra y ofertas relevantes.");
  searchUrl.searchParams.set("location", "EC");
  searchUrl.searchParams.set("language", "es");

  try {
    const controller = new AbortController();
    const timeout = setTimeout(() => controller.abort(), 15_000);
    const response = await fetch(searchUrl, {
      headers: { "X-API-Key": apiKey, "Accept": "application/json" },
      signal: controller.signal,
    }).finally(() => clearTimeout(timeout));

    if (!response.ok) {
      console.error("TinyFish search failed", { status: response.status });
      return json({ error: "No fue posible consultar las fuentes web ahora." }, 502);
    }

    const payload = await response.json();
    const results = Array.isArray(payload.results) ? payload.results : [];
    return json({
      query,
      offers: results.slice(0, 10).map((result, index) =>
        offerFromResult(result, index + 1, query)
      ),
      searchedAt: new Date().toISOString(),
    });
  } catch (error) {
    console.error("TinyFish request could not be completed", error);
    return json({ error: "La búsqueda web no está disponible en este momento." }, 502);
  }
});

Elige una de estas dos rutas:

Dashboard

  1. Abre Edge Functions → Secrets.
  2. Agrega TINYFISH_API_KEY.
  3. Pega el valor y guarda.

CLI, sin dejar la clave en el historial

  1. En el archivo .gitignore de IATinyFish/, agrega una línea: supabase/.env.production.local.
  2. Crea supabase/.env.production.local y escribe una línea: TINYFISH_API_KEY=YOUR_TINYFISH_API_KEY. Sustituye el valor por tu clave real solo en ese archivo.
  3. Antes de continuar, comprueba desde la terminal que el archivo está ignorado con git check-ignore supabase/.env.production.local, si trabajas con Git.
  4. En la terminal de IATinyFish/, ejecuta los dos comandos siguientes. No copies el contenido del archivo como si fueran comandos.
npx supabase secrets set --env-file supabase/.env.production.local
npx supabase secrets list
Los secretos se aplican sin redesplegar

Supabase hace que el nuevo valor esté disponible para las funciones desplegadas. La lista muestra nombres y huellas, no debe revelar el valor.

2. Despliega la función

Desplegar significa enviar el archivo local index.ts a tu proyecto de Supabase para que pueda responder por Internet. La URL incluye tu PROJECT_REF y el nombre search-products. Anótala: primero la probarás desde la terminal y luego configurarás Android con su parte base.

npx supabase functions deploy search-products

La URL resultante sigue este patrón:

https://YOUR_PROJECT_REF.supabase.co/functions/v1/search-products

3. Prueba la función alojada

Esta prueba separa backend y app. Envía una consulta directamente a Supabase desde la terminal. Si recibes una lista offers, sabes que Supabase pudo leer el secreto, llamar a TinyFish y transformar la respuesta; cualquier problema posterior estará en la integración con Android.

curl --request POST \
  'https://YOUR_PROJECT_REF.supabase.co/functions/v1/search-products' \
  --header 'Content-Type: application/json' \
  --data '{"query":"Nintendo Switch OLED"}'

Como verify_jwt = false, esta variante del laboratorio no necesita apikey ni Authorization. Si recibes 401, la configuración no fue aplicada o la función fue desplegada con verificación habilitada.

  1. En Supabase abre Edge Functions → search-products.

  3. En Logs, filtra por nivel o momento para localizar errores de la función.

6. Practica la rotación del secreto

  1. Crea una nueva API key en TinyFish sin revocar todavía la actual.
  2. Actualiza TINYFISH_API_KEY en Supabase y ejecuta una búsqueda de control.
  3. Cuando la prueba devuelva 200, revoca la clave anterior en TinyFish.
  4. Si una clave llegó a Git, revocarla es obligatorio: borrarla del último commit no la elimina del historial ni de copias existentes.

INTEGRACIÓN ANDROID ↔ SUPABASE

Conectar la app al endpoint alojado

Con el backend ya verificado, activa RemoteDealsRepository al compilar y entrega la base de la URL de Supabase.

Dónde trabajar

Vuelve a la terminal de IATinyFish/ para compilar con las propiedades remotas. Después abre Android Studio y ejecuta la app en el emulador. Si necesitas revisar una petición, consulta las invocaciones en el Dashboard de Supabase. En este paso no copies la clave de TinyFish al proyecto Android.

1. Compila con propiedades remotas

En el bloque Android dejamos listo un repositorio local y otro remoto. La propiedad useRemoteDeals=true selecciona el remoto al compilar; edgeRuntimeBaseUrl le indica a qué proyecto de Supabase dirigirse. Sustituye solo YOUR_PROJECT_REF por el identificador de tu proyecto y ejecuta el comando desde la carpeta que contiene gradlew.

./gradlew :app:assembleDebug \
  -PuseRemoteDeals=true \
  -PedgeRuntimeBaseUrl=https://YOUR_PROJECT_REF.supabase.co/functions/v1

Observa que la propiedad contiene la base y no el nombre de la función. El repositorio agrega /search-products.

Retrofit necesita una URL base válida

Puedes escribir .../functions/v1 o .../functions/v1/: ensureTrailingSlash() normaliza el valor antes de construir Retrofit. No agregues search-products aquí porque ya está en @POST.

2. Ejecuta desde Android Studio

Para que el botón Run use las mismas propiedades:

Compilar desde la terminal crea el APK, pero pulsar Run en Android Studio puede iniciar otra compilación. Por eso ambos caminos deben usar la misma configuración; de lo contrario podrías ver otra vez los datos de demostración y pensar que el servidor falló.

  1. Abre Run → Edit Configurations.
  2. Selecciona la configuración de la app.
  3. Agrega a las opciones de Gradle las dos propiedades anteriores.
  4. Aplica, reconstruye y ejecuta.

Otra opción es colocar valores no secretos en gradle.properties local:

useRemoteDeals=true
edgeRuntimeBaseUrl=https://YOUR_PROJECT_REF.supabase.co/functions/v1
La URL de función no es un secreto

Puede vivir en la configuración del cliente. Lo que debe permanecer exclusivamente en Supabase es la clave privada de TinyFish.

3. Recorre la app

  1. Abre TinyPrice y confirma la pantalla de descubrimiento.
  2. Busca Nintendo Switch OLED.
  3. Observa el estado “Buscando ofertas…”.
  4. Confirma que el subtítulo dice “encontrados en la web”, no “de demostración”.
  5. Abre una tarjeta y toca Abrir fuente web.
  6. Regresa a la app y prueba una segunda consulta.

4. Inspecciona sin filtrar secretos

Puedes registrar el código HTTP y el tiempo de respuesta durante desarrollo, pero evita imprimir encabezados completos, cuerpos que contengan datos sensibles o secretos.

Pruebas automatizadas del ViewModel

Inyecta un repositorio falso y controla Dispatchers.Main con kotlinx-coroutines-test. Cubre al menos consulta vacía, éxito y error remoto.

Estas pruebas se ejecutan en tu computadora y no requieren un emulador. El repositorio falso devuelve respuestas previsibles para comprobar las decisiones del ViewModel: cuándo empieza la carga, qué muestra si llegan resultados y qué mensaje deja si falla la búsqueda.

@OptIn(ExperimentalCoroutinesApi::class)
class DealsViewModelTest {
    @get:Rule val mainDispatcherRule = MainDispatcherRule()

    @Test fun validQueryPublishesResults() = runTest {
        val offer = sampleOffer()
        val viewModel = DealsViewModel(
            FakeDealsRepository(result = listOf(offer)),
        )

        viewModel.onEvent(DealsEvent.QueryChanged("Switch OLED"))
        viewModel.onEvent(DealsEvent.SubmitSearch)
        advanceUntilIdle()

        assertFalse(viewModel.state.value.isLoading)
        assertEquals(listOf(offer), viewModel.state.value.offers)
    }
}

La referencia incluye también MainDispatcherRule, el repositorio falso y casos para validación y fallo. Ejecuta:

./gradlew :app:testDebugUnitTest

Prueba instrumentada de Compose

Esta prueba sí necesita un emulador o dispositivo encendido, porque comprueba componentes de la interfaz Android. Ejecútala después de confirmar que la app compila y que el dispositivo aparece conectado.

class DealsAppTest {
    @get:Rule val composeRule = createComposeRule()

    @Test fun startScreenShowsSearchAndSuggestion() {
        composeRule.setContent {
            IATinyFishTheme {
                DealsApp(state = DealsUiState(), onEvent = {})
            }
        }

        composeRule.onNodeWithText("Buscar").assertIsDisplayed()
        composeRule.onNodeWithText("Nintendo Switch OLED").assertIsDisplayed()
    }
}
./gradlew :app:connectedDebugAndroidTest

Lo que implementaste

Vuelve mentalmente al inicio: primero comprobaste qué entrega TinyFish, luego hiciste una app que funciona con datos locales y por último añadiste una función en la nube. El mismo repositorio Android pudo cambiar de fuente sin rehacer su interfaz. Esa separación es la idea principal del ejercicio.

  • UI Compose con descubrimiento, búsqueda, carga, error, lista y detalle.
  • Estado inmutable y eventos con ViewModel + StateFlow.
  • Repositorios intercambiables para demo y búsqueda real.
  • Función TypeScript desplegada en Supabase Cloud.
  • Secreto de TinyFish fuera del APK.
  • Transformación de resultados y enlaces verificables.

Publica primero en una pista interna

  1. Incrementa versionCode y revisa nombre, icono, permisos, textos legales y política de privacidad.
  2. En Android Studio abre Build → Generate Signed Bundle / APK y elige Android App Bundle.
  3. Crea o selecciona una upload key. Guarda el keystore y sus contraseñas fuera del repositorio y con una copia de respaldo protegida.
  4. Genera la variante release y localiza el archivo .aab.
  5. En Play Console crea la aplicación, configura Play App Signing y completa la ficha, Data safety y política de privacidad.
  6. Sube el AAB a Internal testing, añade testers y valida instalación, búsqueda, apertura de fuente y errores antes de promover la versión.
No publiques todavía el endpoint didáctico

Con verify_jwt = false cualquier persona puede consumir la función y abusar de la clave del proveedor. Para una distribución abierta, implementa autenticación, autorización, rate limiting compartido, límites de gasto y alertas antes de promover la app a producción.
